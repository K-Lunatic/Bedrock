# 컴퓨터구조

과거 컴퓨터구조 수강과 강의 소개의 CPU 동작·연산·명령어·메모리/캐시 목표를 확인했습니다. 아래는 해당 범위를 복습하기 위한 새 요약이며 Notability 세부 필기는 아직 반영하지 않았습니다.

## 핵심 정리

### 1. 명령어 실행

CPU는 명령어를 가져오고 해석한 뒤 연산이나 데이터 이동을 수행한다. 프로그램 카운터는 실행할 명령어 위치를 추적하고 레지스터는 연산에 사용할 값을 보관한다. 실제 CPU는 파이프라인 등으로 여러 단계를 겹쳐 실행할 수 있다.

### 2. 정수 표현

부호 없는 8비트 값은 0부터 255까지 표현한다. 같은 비트열도 자료형과 해석에 따라 다른 값을 뜻한다. 고정 폭 연산의 넘침을 고려하며 C의 부호 있는 정수 오버플로를 단순한 순환 계산으로 가정하지 않는다.

### 3. 메모리 계층

레지스터·캐시·주기억장치는 접근 속도와 용량·비용이 다르다. 최근 데이터를 다시 쓰는 시간 지역성과 가까운 주소를 이어 쓰는 공간 지역성이 캐시 활용에 영향을 준다.

### 4. 성능 계산

단순 평균 모델에서 CPU 시간은 명령어 수 × 평균 CPI ÷ 클럭 주파수로 계산한다. 같은 명령어 수와 평균 CPI라면 주파수가 두 배가 될 때 계산된 CPU 시간은 절반이다. 실제 전체 실행 시간은 메모리와 I/O 등도 영향을 준다.

### 5. 입출력과 인터럽트

폴링은 상태를 반복해서 확인하는 방식이고 인터럽트는 사건을 알리는 방식이다. 인터럽트 처리는 짧게 유지하고 오래 걸리는 처리는 주 실행 흐름이나 작업으로 넘기는 구성을 검토한다.

### 6. 게임·임베디드에 연결

게임 프레임 처리의 데이터 배치와 캐시, MCU의 레지스터·인터럽트·메모리 제한을 연결해 복습한다. ESP32는 칩별 CPU·핀·메모리 구성이 다르므로 보유 모델의 데이터시트와 보드 회로도를 확인한다.
