# 데이터베이스

과거 데이터베이스 수강 목록, 로컬 MySQL 함수 실습과 Obsidian의 모델링·트랜잭션 노트를 확인해 새로 정리했습니다. 실제 DB 덤프와 개인 레코드는 첨부하지 않았습니다.

## 핵심 정리

### 1. 모델과 제약조건

기본 키는 행을 식별하고 외래 키는 테이블 사이의 참조 관계를 표현한다. NOT NULL과 UNIQUE 같은 제약을 사용해 잘못된 상태가 DB에 들어오는 것을 줄인다.

### 2. 관계와 정규화

다대다 관계는 중간 테이블로 표현할 수 있다. 정규화는 같은 사실의 중복과 갱신 불일치를 줄이는 방향으로 관계를 나눈다. 읽기 성능만 보고 중복 저장하면 수정 경로의 일관성 비용이 늘 수 있다.

### 3. SQL과 NULL

MySQL에서 CONCAT은 문자열을 연결한다. 숫자 덧셈과 문자열 연결을 구분한다. NULL 여부는 IS NULL 또는 IS NOT NULL로 검사하며 = NULL 비교로 대체하지 않는다. 문자 수와 저장 바이트 수도 구분한다.

### 4. 트랜잭션

트랜잭션은 함께 성공하거나 취소되어야 할 변경을 묶는다. 커밋은 변경을 확정하고 롤백은 취소한다. 원자성은 전체 반영 또는 전체 취소라는 성질이며, MySQL의 실제 동작에는 트랜잭션 지원 엔진과 자동 커밋 설정도 영향을 준다.

### 5. 인덱스와 동시성

인덱스는 조회를 돕지만 저장 공간과 쓰기 비용이 생긴다. 실행 계획과 실제 조회 조건을 보고 선택한다. 트랜잭션을 쓴다고 모든 갱신 충돌이 자동으로 사라지는 것은 아니므로 격리·잠금·조건부 갱신도 확인한다.

### 6. 게임·임베디드에 연결

게임의 저장 데이터·점수·아이템 관계와 센서 기록을 생각하며 복습한다. 작은 MCU에 서버 DB를 무조건 올리기보다 기기 내 설정 저장과 서버의 기록 저장을 나누어 설계한다. 실습은 가상 데이터로 한다.
